# 🎨 · DrawGen

第三方生图扩展。

## 1.8.17 优先拿图片数据 + 外链迟到补存 + 状态条加高

- images 兜底改回「先要 `b64_json`」：站点给图片数据就直接上传存本地，不用下载、不受跨域影响；站点明确 400 拒绝该参数才改要 `url` 重试一次。
- **外链迟到补存**：如果生成时下载被拦、只能存了外链，插件会在约 90 秒和 10 分钟后各重试一次「下载→上传」，成功就把聊天里那条外链原地换成本地路径（只换完全相同的那一条，失败不动任何数据）。
- **状态条加高并可滚动**：失败原因不再被截断；生成完成的状态会区分「已存成本地文件 / 只存了外链 / 只存了内嵌数据」。

## 1.8.16 外链下载加酒馆代理兜底

- 很多站点返回的是**1 小时有效的签名外链**（例如 `r2.cloudflarestorage.com/...?X-Amz-Expires=3600`）。浏览器直接下载这种链接常被跨域拦住，插件只能把外链写进聊天，1 小时后链接作废 → 楼层图裂、且本地没有文件，**这类图无法找回**（1.8.11 时期生成的即属此类）。
- 现在直连被拦时会改走酒馆内置的 `/proxy/` 由酒馆服务器代下载，拿到图片数据后照常上传存成本地文件。两条路都不通才退回存外链，并在状态条明确提示「只存了外链（下载被拦，可能过期）」。
- **如果看到这条提示**：打开酒馆目录下的 `config.yaml`，把 `enableCorsProxy: false` 改成 `enableCorsProxy: true`，重启酒馆。之后那个站的图就能存成本地文件、不再过期。
- 按文件头识别图片类型：站点/代理把图当 `application/octet-stream` 返回时也能正确存成 png/jpg/webp/gif。

## 1.8.15 旧图清理改为「保留张数」上限 + 旧引用纠正放宽

- 「存图天数」改为「保留张数」（默认 200）：只保留最新的 N 张本地图片，超出的旧图连服务器文件一起删、聊天里的引用一并摘掉；0 = 不清理。不再按天数。
- 分界线会存进设置，其它聊天打开时也按它摘掉超限引用，不会出现"文件没了、引用还在"的图裂。
- 删文件的路径改成 `user/images/<目录>/<文件>`（和上传返回的一致）；原先少了 `user/`，所以之前的"按天清理"其实一直没删成功过。
- 旧引用纠正放宽：只要引用落在 `DrawGenRecovered/` 目录下（不管前面带不带斜杠、`images/` 或域名）都纠正为 `user/images/DrawGenRecovered/…`，并且插件一加载就跑一遍，不用等切聊天。**更新后请整页刷新一次酒馆**，旧楼层的图裂才会恢复。

## 1.8.14 修「楼层图裂、图库里却能看到」

- 原因：早期离线修复脚本把聊天里的内嵌图抽成文件时，写进聊天的引用少了 `user/` 前缀（写成 `images/DrawGenRecovered/…`，文件实际在 `user/images/DrawGenRecovered/…`）→ 楼层里一直 404 图裂，而酒馆图库里能看到、能下载。
- 插件现在打开聊天时会把这类旧引用一次性纠正回正确路径并落盘（只改这一个前缀，其它路径一律不碰）；脚本本身也已修正。
- 更新后打开出问题的那份聊天，图裂的图会自己恢复（文件一直都在，只是地址写错了）。

## 1.8.13 失败不再自动补发（防重复扣费）

- 网络层失败（浏览器报 Failed to fetch / 连接被掐）**不再自动改打 images 接口**：连接中断只说明我们没拿到响应，站点可能已经生成并扣费，再打一发就是重复扣费。现在直接报错，写明「未自动重试，要重试请自己点重画」。
- 站点明确回 404/405/501/400（接口不存在或参数被拒，肯定没扣费）时，仍允许唯一一次换 images 兜底。
- 「测试」按钮不再真实生图（原先点一下等于真生成一张、真扣费），改成只检查站点可达性（不生成、不扣费）。
- 生图代理勾选改名「走酒馆后端代理（绕跨域）」：它对 Grok / GPT / 任何自定义站都有效——请求从酒馆服务器发出，浏览器不参与，绕开跨域限制。注意：勾上后不发送「尺寸 / 画质」两个参数，也没有 chat 失败退 images 的兜底；只对「扣费了、图收不到」的站勾。

## 1.8.12 图片落盘回到 1.8.9 行为

- 生成好的图统一落盘：接口回外链就先下载成图片数据，再上传到酒馆服务器存成文件，聊天里只留本地路径 `images/…`。
- 接口直接回 Base64 也上传存成文件；只有下载或上传失败时才退回内嵌数据 / 原始外链兜底。
- 撤掉 1.8.11「只认外链、Base64 只弹预览不落盘」两条——这就是「有些不写入聊天」的来源。
- 保留 1.8.11 的聊天保存串行队列；发现过大的旧内嵌图片时仍会暂停插件保存和生图，不删除原记录。
- 移除「锁脸」（参考脸 + `/images/edits` 编辑接口）——它会对同一个请求依次试四种形状，站点后台最坏出现四次生图调用。
- 「存图天数」继续按天清理插件自己生成的本地图片文件（文件名 `sdg_<时间戳>_…`）。

## 已有大聊天的离线修复

先停止 SillyTavern。以下脚本只使用 Node 内置模块，手动执行，不会被插件加载。

在本插件目录先检查（不改文件）：

```bash
node --max-old-space-size=64 scripts/repair-inline-images.cjs --root "$HOME/SillyTavern"
```

执行修复：

```bash
node --max-old-space-size=64 scripts/repair-inline-images.cjs --root "$HOME/SillyTavern" --apply
```

脚本逐段读取活动聊天与群聊，跳过酒馆备份，只把插件 `sdg_gal`、`sdg_images`、`sdg_image` 中的内嵌图片提取成独立文件；聊天文字、回复历史和其他插件内容保持不变。每份原聊天先备份并核对哈希，图片和新 JSONL 验证通过后才替换原文件。畸形输入、写入失败或检测到原文件发生变化时不替换。

原文件备份在 `SillyTavern/drawgen-repair-backup-日期/`，图片在对应用户的 `data/<user>/user/images/DrawGenRecovered/`。恢复图片的保留天数从修复日期开始算。备份会保留原来的大文件，不会自动删除；它们不在酒馆的活动聊天目录中。

需要撤销时，先关闭酒馆，把备份目录内对应的聊天文件复制回原相对路径。看到 `failed` 大于 0 时保留输出，不要删除聊天；更新插件本身也不会自动缩小已有大文件。
